# Atlas

React 19 and Vite 8, with TanStack Router (file-based routes) and TanStack Query, and Tailwind 4 with an owned shadcn kit on Base UI.

## Layout

```
src/
  main.tsx               router and query client
  routes/                file-based routes; routeTree.gen.ts is generated by the Vite plugin and committed
  api/                   one query/mutation file per backend module
  api/client/            axios client, ApiError, session refresh, query client
  features/<name>/       components, hooks and stores of one feature
  components/ui/         shadcn components
  components/layout/     anything related to layout
  components/fallbacks/  the pages the router falls back to (not found, route error)
  hooks/, lib/           shared hooks and utilities
```

## Talking to the API

- `api` in `src/api/client/api-client.ts` is the axios instance. Its base URL is `/api`, which the dev server proxies to the backend on port 3030; `VITE_API_URL` points it at another origin. Cookies go with every request.
- A 401 triggers one refresh, shared by every request that failed at the same time, and one retry. If the refresh fails too, the query cache marks the user logged out.
- Failures are `ApiError`s with the status and the parsed `ErrorBody`; `body` is undefined when the response didn't come from the API (a proxy's 502 page, say).
- Queries retry network and server errors up to three times, never 4xx.

## Auth and routing

- `authQueries.me()` is the source of truth: the logged-in user, or `null`.
- Routes under `routes/_authenticated/` need a login. `_authenticated.tsx` checks `me` in `beforeLoad`, redirects to `/login?redirect=…`, and passes the user down as `context.user`; login and register send the user back there.
- Logging in drops every cached query, so nothing the previous user saw can show. Logging out only sets `me` to `null`, and the guards take it from there.
- An unknown URL renders `components/fallbacks/not-found.tsx`, and a route whose `beforeLoad`, loader or render throws renders `route-error.tsx` beside it, which shows the message and retries with `router.invalidate()`. Both are router-wide defaults set in `main.tsx`.
- The theme comes from the user's settings. `localStorage` keeps a copy that `index.html` applies before the first paint.

## Development pages

`routes/_authenticated/dev/` holds pages for working on the app, not for its users. `/dev/playground` (admins only) runs valid and invalid calls against the users, settings and items endpoints and shows each response. `/dev/counters` (admins only) shows two counters, each with its own Zustand store.

## UI kit

`src/components/ui/` holds shadcn components copied in as source. There is no shadcn package, CLI or `components.json`: the code is ours to edit, and the parts of shadcn's CSS it needs live in `src/index.css`.

## Commands

From the repo root:

| Command                          | Purpose                               |
| -------------------------------- | ------------------------------------- |
| `pnpm dev:atlas`                 | Dev server at <http://localhost:3000> |
| `pnpm --filter atlas test:watch` | Unit tests in watch mode              |
| `pnpm --filter atlas build`      | Typecheck and build into `dist/`      |
| `pnpm --filter atlas preview`    | Serve the build locally               |

In development, two buttons in the bottom corners open the query cache (right) and the router (left) inspectors; production builds leave them out.
